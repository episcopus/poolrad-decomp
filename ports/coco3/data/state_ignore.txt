# statecheck.py: globals (or the storage arrays Raw<addr>/ds<addr>) of DGROUP that cannot be equal after the same session on the
# CoCo and on the PC, with the reason. One per line: name, a space, the reason. Anything not listed here and different is a finding.
# "OPEN:" marks a difference nobody has explained yet; it is reported like a finding and keeps the check red (none now).
#
# Turbo Pascal's System, Dos, Crt and Overlay variables and the files of the start-up: the CoCo has no counterpart
OvrHeapSize System: the overlay manager's buffer (the CoCo's banks have their own manager)
OvrHeapOrg System: the overlay manager's buffer
OvrHeapPtr System: the overlay manager's buffer
OvrHeapEnd System: the overlay manager's buffer
HeapOrg System: the PC's heap (the CoCo has two heaps, rtl_heap.c)
HeapPtr System: the PC's heap
HeapEnd System: the PC's heap
FreeList System: the PC's heap
NewHeapEnd System: res08 init, the PC's heap limit
PrefixSeg System: the PSP segment
RandSeed System: the CoCo's generator is rand_seed (rtl_sys.c), the same sequence in another place
FileMode System: DOS file mode
LoaderFile File record of the PC: a TP file variable (the CoCo's files are rtl_file.c's)
CfgChar res08 init: POOL.CFG is not read on the CoCo (platform.c gives the answers)
CfgText res08 init: the Text variable of POOL.CFG
CfgProbe res08 init: probe buffer of POOL.CFG
FileProbeResult The IOResult of the last FileExists probe (the codes of DOS and of rtl_file.c differ)
Regs Dos: the register record of the last Intr call
LastMode Crt: the text mode
TextAttr Crt: the text attribute
WindMax Crt: the text window
Input System: the Text variable of standard input
Output System: the Text variable of standard output
# The engine keeps what the PC's video code kept in DGROUP
ActivePageSegment res06: the EGA page segment (the engine owns the screen)
FillPageSegment res06: the EGA page segment
CurrentVideoMode res07: SetVideoMode is the engine's and does not write this variable
RowFirstChangedCol res07: the changed-rows trackers of DrawBuf (the engine has its own, gfx.c)
IconBackgroundBuffer res07: a picture pointer (a handle on the CoCo)
SoundMode res08 init: the CoCo starts with the sound driver off (8.9)
SoundModeBeforePause res06: sound state (8.9)
SoundDriverIdle res03: sound driver state (8.9)

GameFont picture pointer (a handle)

SqrPaciBank1 picture pointer (a handle)
SqrPaciBank2 picture pointer (a handle)
Raw5E5A the picture slots: pointers (handles)
PictureSlots picture pointers (handles)
ds5F1A the dying picture and the table next to it: pointers (handles)
CombatantTable pointers to combatants
WallSets pointer to a heap block
GeoBlock pointer to a heap block
LoadSlots pointers to heap blocks
HeadSpriteBank picture pointer (a handle)
BodySpriteBank picture pointer (a handle)

# Representation again, found by looking at the bytes
Raw6B84 the table of spell handlers (ids of routines) and the byte after it
Raw6C91 the spell targets: far pointers (a combatant's address on the PC, on the CoCo the mapped heap's)
SpellTargets the spell targets: far pointers
EclStrings a string buffer's tail beyond its length (one byte of old data): not observable
Raw70C7 SharedLoopIndex: a loop control variable, undefined after the loop in Pascal (12 on the PC, 0 here)
ReselectCharacter pointer to a character
ds471A pointers to characters (ViewedCharacter and the bytes after it)
ViewedCharacter pointer to a character
ds471D the affect flags of the viewed character, next to its pointer
TimedAffectFlags the affect flags next to ViewedCharacter's pointer
SelectedCharacter pointer to a character
PartyListHead pointer to the first character of the party
PictureAnimation the sprite list of the area view: picture pointers (handles) in its slots, the rest equal
ds6ABE the sprite list and the bytes before it: picture pointers (handles)
CombatMap pointer to the combat map block (an address of the CoCo's mapped heap)
ds6716 the low word of CombatMap (a pointer)
Raw6718 the low word of CombatMap seen as the bytes after the pointer's first word, and the table behind it (SortEntries)
CombatantRecord the table of pointers to the combatants (addresses of two different heaps)
SortEntries the first bytes are the low word of CombatMap (the pointer overlaps the sort table's first record, as on the PC where its segment does), see CombatMap
Raw6E36 CombatAnimationPicture: a picture handle here, a pointer there
BodyTable the first four bytes of an entry are a pointer to the character that died (the rest is equal)
AttackTarget a pointer to a character
Raw6826 the low word of AttackTarget (a pointer)
ds6828 the low word of AttackTarget (the pointer's second word overlaps the table that follows, as on the PC)
AffectHandlers its first word is the low word of AttackTarget's pointer (the same overlap)
SpellMenuList the head of the spell menu list: a pointer into a heap (the list is freed again when the menu closes; the stale pointer stays)
PickedSpellCharacter the character the spell picker chose: a pointer into a heap
Raw6C95 the same pointer seen as the first bytes of the table behind it
PooledItems the head of the loot list: a pointer into a heap (the party record check compares the characters themselves)
