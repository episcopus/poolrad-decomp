# AGENTS.md: operating manual for AI agents

You are working on a **matching decompilation of SSI's Pool of Radiance (DOS) into Turbo Pascal 6.0**: Pascal source that the original compiler turns into the original's machine code, routine by routine, proven by `make match`. A C translation comes later (Phase 7). This file is the canonical instruction set for every harness (Claude Code, Cursor, OpenCode, others). Read it fully at the start of every session.

## Read first

1. `docs/spec/SPEC.md`: goals, approach (ADR-002), verification ladder, phases. It wins over anything else except a direct human instruction.
2. `work/status.md`: where the project stands (generated by `make status`).
3. The playbook for your task in `docs/process/playbooks/` (index below). For decompiling: playbook 30.
4. `docs/design/WHITEPAPER.md`: what is already known about the game. Do not rediscover it; extend it.
5. Running in parallel with other agents: `docs/process/KICKOFF.md` (roles, prompts) and the playbook for your role. Agents are started and stopped by the human operator, possibly in different harnesses; you coordinate only through the repository and the shared files (`make locks`, `make handoffs`, `make agents`).

## Facts you must not get wrong

- The original program is **Turbo Pascal 6.0 (June 1991 release)**, 16-bit real mode, with **35 overlay units** in `GAME.OVR` (`FBOV`) and **15 known resident units**: 13 in the init chain plus the Borland Dos (`res13`, `0A32`) and Overlay (`res14`, `0AA2`) units, which have no init.
- **The runtime units are library.** System (`res00`), Crt (`res01`), Dos (`res13`) and Overlay (`res14`) are the compiler's own units from `TURBO.TPL`: linked, never decompiled.
- **Compiler switches:** `{$A-,F+,S-,R-,G-,I-}` for every unit, `O+` added for every overlay unit and, per unit, for the resident units whose code shows it (res07 and res08: string literals copied to a stack temporary first; whitepaper 2.2 and 3.6), `I+` only in res05. Not TP 7.0 and not the October 1990 TP 6.0 (`make tp-compare`). TP 6.0 has no `const` parameters and no `$Q`.
- **The compiler is on the critical path but proprietary:** it lives in `build/toolchain/` (ignored by git; `make tp-pin`, `docs/setup/SETUP-tp.md`) and is never committed, pushed or copied into `src/`.
- Analyse `poolrad/start-unpack.exe` (the unpacked image), not `START.EXE` (EXEPACK packed).
- `re/symbols.toml` boundaries are approximate until a routine matches: a size is the gap to the next entry (so it includes the next routine's literal pool), and the map can merge or invent routines. `make match WRITE=1` writes the compiler's boundaries into the registry (sizes, entries inside matched code removed, missing routines added); there is no mapper role.
- **External object files.** Code the original linked from an `.OBJ` (`{$L}`, placed after the unit's initialisation part) is not Pascal: `re/units.toml` names it (`external_from`), the registry flags its routines `external = true`, the matcher keeps it as the original's bytes and the unit can still be complete (res03's sound driver). Phase 5 rebuilds it from an assembly source.
- Our build differs from the 1988 build other projects analysed (38 overlays, `TPOV`). Their addresses never apply to us; their findings are leads to re-prove.

## Ground rules

1. **Evidence or it did not happen.** Every name, type and claim cites an address, a tool output or a test. Prior art and your own recall are leads, tagged [H] until proven on our bytes. How Turbo Pascal compiles an idiom is settled with `make tpc`, never by recall.
2. **Tools write verdicts, you do not.** Never edit a level by hand (`make match WRITE=1` writes L2 and the compiler's boundaries). A decompiler or reviewer never changes the matcher, the tests or the spec: the git pre-commit hook and the harness edit guard refuse it (`tools/agent/hooks/`); a matcher gap is a tooling task. A matcher change merges when `make match-gate` passes (every L2 routine still matched, together and alone; every negative fixture still rejected; a new address kind brings its negative fixture) and the commit says why; the human reads the diff afterwards. Byte equality of code and literal pools is the invariant the gate tests. No raw machine code (`inline(...)`, `db` bytes) to force a match.
3. **Stay in your lane.** Work only on a unit you claimed (`make claim AGENT=<you>`: it locks the unit and gives you a worktree on branch `unit/<id>`; the same agent may reclaim its own lock), and only in that worktree. Edit only `src/<UNIT>.PAS` and `re/` entries for its routines. Never merge into `main`, never commit `work/status.md` or `work/blockers.md`: `make integrate` merges every hand-off mechanically and writes both files (playbook 90). Additive edits to shared files are allowed: a global in `src/POOLVARS.PAS`, a name in `re/dseg.toml`, a `{@stub}` declaration (signature only, also recorded as `signature` in `re/symbols.toml`, from which `make stubs` regenerates every stub line) in another unit's file; the shared files merge record by record (`make merge-driver`), so two branches conflict only on the same record. Every matched routine must still match afterwards (`make check`).
4. **Never touch** `poolrad/` (pinned originals), `build/` contents in commits, or code from sources whose licence forbids reuse (see `docs/reference/prior-art.md`: coab, wicanr2, GPL projects are read-only references).
5. **Small commits.** One routine or a few related routines per commit. Message format: `<unit>: <what> (<routine ids>) [Lx]`, with a trailer line `Agent: <your agent name>` (reviews check it).
6. **Stop and ask the human** before changing: the spec or an ADR, the session set or `re/state.toml`, the matcher's rules, anything under `poolrad/`.
7. **Bounded effort.** After 5 failed attempts on one routine, stop, write a `blocked` note in `re/symbols.toml` (`notes`) with what you tried, and move on. Under `make worker` a routine two sessions could not match goes to the frontier (`.git/poolrad-frontier/`, shown by `make inbox`) and is not offered again until released.
8. **Keep the design doc alive.** The decompiler of a unit updates `docs/design/WHITEPAPER.md` with what the unit taught and gives its changelog row in the hand-off (`CHANGELOG=`); only `make integrate` writes `docs/design/CHANGELOG.md` (playbook 60). Questions you cannot settle from evidence go to the human's inbox as `make handoff STATE=escalate` (`make inbox` lists them with the command that records the decision).
9. **Keep the human informed.** A silent agent looks hung. A worker started by `make worker` is covered: the supervisor posts its heartbeats, hands off when a session ends and never leaves a lock behind; the rest of this rule is for sessions a human runs by hand. Post `make heartbeat AGENT=<you> NOTE="<what you are doing now, what comes next>"` when you start each step (a claim, a routine, a long `make check`, a hand-off) and at least every 20 minutes while you work, including during long builds, waits, and while stuck; say the same in one line in your own session. When you stop, `make heartbeat AGENT=<you> NOTE="<why>" DONE=1`. `make claim` and `make handoff` post one for you, and `make match`, `make check`, `make packet` and `make tpc` refresh yours (keeping your last note), so you show as alive while you work; a NOTE saying what you are doing is still yours to post. `make agents` shows everyone's last heartbeat. An empty queue is not a reason to stop: post an idle heartbeat, wait about 5 minutes and look again; stop only when the human says so or no more work can arrive (both queues empty and no unit lock held by another agent).
10. **Write plainly.** No em dashes or en dashes in any file or message; use commas, colons, semicolons or parentheses.
11. **No self-appointed operators.** (One delegation exists: the human's `make start-run` roster gives the orchestrator session the inbox decisions and lock recovery for that run, within the limits of its KICKOFF prompt; the spec, ADRs, the session set, `re/state.toml` and `poolrad/` stay the human's.) The human-only agent lifecycle rule applies to parent/launcher sessions too, not just `orch`. A request to keep working, resolve low-risk blockers or work overnight does not authorize starting replacement agents, changing staffing or approving a human-reserved decision. Ask for explicit authorization for each launch or a bounded batch. Never impersonate the operator with `OPERATOR=1`; operator commands must be restricted by the harness, not just by this file.
12. **Respect shared control and work ownership.** Before each routine/review and after every wait, run `make agent-step AGENT=<you>` (docs/process/SAFETY.md). Draining: finish your current task and hand off, then stop without claiming more. Paused/stopped: start no new routine; preserve and hand off your work. A dirty main checkout means wait for the orchestrator, never stash, reset, clean or commit it. Never pop a shared stash. Hand-offs pin a commit and require your own lock/worktree; only `orch` clears them after a passing check of the merged inputs. Never release another agent's lock or delete its worktree.
13. **Reuse and attribute work.** At creation register actual ROLE, HARNESS, full MODEL/VARIANT and harness SESSION, never guessed metadata. Use the `make` wrappers so tasks, failures and tool time carry immutable agent/task ids. Read the packet's learning brief, accepted main's whitepaper and `docs/reference/prior-art.md`; search `make learn` before another probe. Save concise evidence-linked lessons in `re/learnings/<unit>.toml` and new probes under `tools/re/tp_idioms/<unit>/`. Do not overwrite existing shared probes. Historical missing identity/cost stays unknown.
14. **Expert advice is bounded, not authority.** The human may pre-start one powerful-model expert and admit its externally capped budget. The orchestrator may queue eligible cases through `make expert-scan`, not spawn an agent. One active case, five/run, one/problem/input revision, 15-minute lease, USD 10 case and USD 50 run allocations. Unknown usage and overage hold dispatch; never reset quotas, replace the session or recursively delegate. Experts do not edit game code/verdicts or approve human decisions. The original worker must re-prove any suggestion, and publish verified learning. Repository allocations/deadlines are not a provider billing/process cap (THROUGHPUT.md).

## Source conventions (summary; SPEC section 7 is authoritative)

- One file per original unit: `src/<ID>.PAS`, `unit <ID>`, routines in address order, every routine declared in the interface, top-level headers in column 1. Every unit already has a skeleton; `src/POOL.PAS` is the main program.
- Names: routines keep their `re/symbols.toml` name until renamed there; globals are `dsXXXX` (their DS offset) until named in `re/dseg.toml`; unattributed globals live in `src/POOLVARS.PAS`.
- A routine not decompiled yet is a `{@stub}` (header line starts with it, empty body); give it the right signature when a caller needs it and record that in `re/symbols.toml` `signature`. An initialisation part with real code not decompiled yet is marked `{@stub-init}`.
- Faithful: same control flow and evaluation order, original quirks kept (the compiler will not accept anything else).
- **Readable before committing** (`docs/process/READABILITY.md`): every routine you decompile gets a real name, named parameters, locals and constants, names or commented declarations for the globals it uses, and a comment with its address and meaning. `make readability` (part of `make check`) refuses what was skipped. Rename routines of your unit and globals you have evidence for with `make rename OLD= NEW= WHY=`; leave other units' routines to their decompilers.
