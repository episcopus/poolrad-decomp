# AGENTS.md: operating manual for AI agents

You are working on a **matching decompilation of SSI's Pool of Radiance (DOS) into Turbo Pascal 6.0**: Pascal source that the original compiler turns into the original's machine code, routine by routine, proven by `make match`. A C translation comes later (Phase 7). This file is the canonical instruction set for every harness (Claude Code, Cursor, OpenCode, others). Read it fully at the start of every session.

## Read first

1. `docs/spec/SPEC.md`: goals, approach (ADR-002), verification ladder, phases. It wins over anything else except a direct human instruction.
2. `work/status.md`: where the project stands (generated by `make status`).
3. The playbook for your task in `docs/process/playbooks/` (index below). For decompiling: playbook 30.
4. `docs/design/WHITEPAPER.md`: what is already known about the game. Do not rediscover it; extend it.

## Facts you must not get wrong

- The original program is **Turbo Pascal 6.0 (June 1991 release)**, 16-bit real mode, with **35 overlay units** in `GAME.OVR` (`FBOV`) and **15 known resident units**: 13 in the init chain plus the Borland Dos (`res13`, `0A32`) and Overlay (`res14`, `0AA2`) units, which have no init.
- **The runtime units are library.** System (`res00`), Crt (`res01`), Dos (`res13`) and Overlay (`res14`) are the compiler's own units from `TURBO.TPL`: linked, never decompiled.
- **Compiler switches:** `{$A-,F+,S-,R-,G-,I-}` for every unit, `O+` added for overlay units, `I+` only in res05 (whitepaper 2.2). Not TP 7.0 and not the October 1990 TP 6.0 (`make tp-compare`). TP 6.0 has no `const` parameters and no `$Q`.
- **The compiler is on the critical path but proprietary:** it lives in `build/toolchain/` (ignored by git; `make tp-pin`, `docs/setup/SETUP-tp.md`) and is never committed, pushed or copied into `src/`.
- Analyse `poolrad/start-unpack.exe` (the unpacked image), not `START.EXE` (EXEPACK packed).
- `re/symbols.toml` boundaries are approximate: a routine's size often includes the next routine's literal pool, and the map can merge two routines. `make match WRITE=1` reports the compiler's boundaries.
- Our build differs from the 1988 build other projects analysed (38 overlays, `TPOV`). Their addresses never apply to us; their findings are leads to re-prove.

## Ground rules

1. **Evidence or it did not happen.** Every name, type and claim cites an address, a tool output or a test. Prior art and your own recall are leads, tagged [H] until proven on our bytes. How Turbo Pascal compiles an idiom is settled with `make tpc`, never by recall.
2. **Tools write verdicts, you do not.** Never edit a level by hand (`make match WRITE=1` writes L2). Never loosen the matcher (a new address kind, a weaker rule) without a written reason in the commit and a human's approval. No raw machine code (`inline(...)`, `db` bytes) to force a match.
3. **Stay in your lane.** Lock the unit you work on (`make lock UNIT=...`). Edit only `src/<UNIT>.PAS` and `re/` entries for its routines. Additive edits to shared files are allowed: a global in `src/POOLVARS.PAS`, a name in `re/dseg.toml`, a `{@stub}` declaration (signature only) in another unit's file. Every matched routine must still match afterwards (`make check`).
4. **Never touch** `poolrad/` (pinned originals), `build/` contents in commits, or code from sources whose licence forbids reuse (see `docs/reference/prior-art.md`: coab, wicanr2, GPL projects are read-only references).
5. **Small commits.** One routine or a few related routines per commit. Message format: `<unit>: <what> (<routine ids>) [Lx]`.
6. **Stop and ask the human** before changing: the spec or an ADR, the session set or `re/state.toml`, the matcher's rules, anything under `poolrad/`.
7. **Bounded effort.** After 5 failed attempts on one routine, stop, write a `blocked` note in `re/symbols.toml` (`notes`) with what you tried, and move on.
8. **Keep the design doc alive.** Each finished unit updates `docs/design/WHITEPAPER.md` and `docs/design/CHANGELOG.md` (playbook 60).
9. **Write plainly.** No em dashes or en dashes in any file or message; use commas, colons, semicolons or parentheses.

## Commands (all from the repository root)

| Command | Purpose |
|---|---|
| `make doctor` | Check the environment and pinned inputs |
| `make inputs` | Verify hashes of everything in `poolrad/` |
| `make overlays` | Regenerate the overlay manifest and extract overlay code (`build/re/`) |
| `make map` | Fill unit ranges, enumerate routines, tag runtime names, refresh status |
| `make tp-pin` | Install the Turbo Pascal compilers from `build/toolchain/dist/`, compare runtimes (`docs/setup/SETUP-tp.md`) |
| `make tpc SRC=x.pas [DISASM=1]` | Compile any Pascal with the pinned TP 6.0; the listing names runtime calls by POOL routine |
| `make packet FN=<id or name>` / `UNIT=<id>` | Work packet: annotated disassembly, frame, callers, current source (`build/packets/`) |
| `make match UNIT=<id> [FN=<name>] [WRITE=1]` | Prove the unit's Pascal against the original (L2); no `UNIT`: every unit with source |
| `make lock UNIT=` / `make unlock UNIT=` | Claim or release a unit |
| `make status` / `make next` | Project status, next unit |
| `make test` / `make test-slow` | Python tests (fast set; the set that boots the game) |
| `make check` | Everything a commit must pass: fast tests, every unit's match, golden check |
| `make oracle-run SCRIPT=<keys>` | Run the original in the emulator (traces, screenshots) |
| `make golden [CHECK=1]` | Record (or verify) session goldens and their recordings |
| `make dax` | Verify DAX container and all data codecs over pinned files |
| `make timing-scan` | Routines that wait on time or input (input for the C translation, Phase 7) |
| `make rebuild` | Relink the whole game from `src/` and compare (Phase 5) |

A target that is not built yet prints which phase delivers it.

## Source conventions (summary; SPEC section 7 is authoritative)

- One file per original unit: `src/<ID>.PAS`, `unit <ID>`, routines in address order, every routine declared in the interface, top-level headers in column 1.
- Names: routines keep their `re/symbols.toml` name until renamed there; globals are `dsXXXX` (their DS offset) until named in `re/dseg.toml`; unattributed globals live in `src/POOLVARS.PAS`.
- A callee that is not decompiled yet is a `{@stub}` with the right signature and an empty body.
- Faithful: same control flow and evaluation order, original quirks kept (the compiler will not accept anything else).
