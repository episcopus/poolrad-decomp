### must-fix

- [ ] must-fix SpellAffectDuration: the comment says the codes above $38 "are affects, not spells". They are spell numbers: the callers pass `ds681B` (ApplySpellToTargets, CastEnlarge, CastHoldPerson, CastStrength, CastMonsterStrength) and the handler table runs to $43. So $28 is spell 40 Cause Disease (1d6*10), $39 spell 57 CastMonsterHaste and $3D spell 61 CastMonsterParalyze (5d4), $3B spell 59 CastMonsterStrength (1d4*10+40, the routine calls it with ds681B), $3F spell 63 CastMonsterInvisibility (2d10*10 in combat) and $43 spell 67 CastMonsterReadMagic ($5A0). The constants `RolledSpell28` ... `FixedSpell43` name the value, not the spell (READABILITY: "the meaning, not the value"). Fix the comment and name them after their spells; the header (ovl22:07D6) should say "spell number", not "spell or affect".
- [ ] must-fix CastCureBlindness: the header and `BlindnessAffect` say $21 is `SpellTable[37].AffectId` and "the affect of spell 37". Row 37 (Cure Blindness) has AffectId 0; $21 is the AffectId of spell 38 Cause Blindness. Cure Blindness removes the affect spell 38 leaves (ovl22:2217). Whitepaper 5.22.2 ("spells 35 to 37") repeats the wrong claim.
- [ ] must-fix CastInvisibility: the header says "its SpellTable affect byte is 0". Row 30 has AffectId $19 (row 50, Invisibility 10' Radius, has $19 too). The next sentence of the same comment (the spell's own affect does the hiding) is the true one; the first contradicts it.
- [ ] must-fix CastKnock: the header says the spell's own affect $1C "opens the lock". Row 31 (Knock) has AffectId 0 and $1C is Mirror Image's affect (row 32). So ApplySpellToTargets applies no affect here and the handler only shows 'Knock-Knock'; the door effect lives elsewhere (ovl14 looks for Knock among the memorized spells, POOLVARS). The comment must say that, not invent an affect. Whitepaper 5.22.2 ("spells 28 to 34") says "only apply the spell's own affect" for Knock and needs the same correction.
- [ ] must-fix CastSleep, CastSlowPoison: `DeadStatus = 1` ("counts as dead (whitepaper 4.2.5)") is wrong. StatusNames (DS:1047, image) is 0 Okay, 1 Animated, 6 Dead, 8 Gone; OVL12 and RES12 name it `StatusAnimated` (OVL12 tests it in DrainLevels "not Dead"), and CastAnimateDead in this very unit uses Status 6 as the corpse and ends with `Status := 1` after the revival. So Sleep and Slow Poison refuse an Animated (undead) target, not a dead one. Rename the constant, fix the comments ("not dead", "still be alive") and the whitepaper sentence "a target that is dead (Status 1)" (5.22.2, spells 13 to 21).
- [ ] must-fix CastSleep: `CostLevel5Small` comment "a level-5 creature of Race 0 (a smaller kind)". RaceNames (DS:0F03) puts 0 at Monster (Monster, Dwarf, Elf, Gnome, Half-Elf, Halfling, Half-Orc, Human). "A smaller kind" has no evidence; say Race 0 is a monster (a hit-dice creature) and that every other level-5 target costs 20.
- [ ] must-fix CastPrayer: the header (ovl22:24D6) has a placeholder where the stub address belongs: "overlay stub 0096:00... ;". Whitepaper 5.22.2 gives 0096:0101. Write the real address.
- [ ] must-fix CastMonsterStrength: the comment on `StrengthAffect = $26` and in the header says $26 is "the affect CastStrength and Enlarge keep the earlier strength in". Enlarge uses $0C (CastEnlarge, SpellTable[12].AffectId, and CastReduce removes $0C); only CastStrength and this routine use $26 (row 35 and row 59 AffectId $26).
- [ ] must-fix CastStinkingCloud: (1) the header says it reads "ds5D96 (SelectedCharacter's side)"; the routine never touches ds5D96 (it reads SelectedCharacter, ds6DB9/ds6DBA, ds6DBB, BodyCount, BodyTable, CombatTiles, CombatMap, CombatantRecord). (2) `CloudEdgeTile = $1F` "the second cloud tile ... meaning open" contradicts the header, which says a cell whose tile is $1F "borrows the tile of a body there (BodyTable)": the code looks $1F up in BodyTable by cell, so $1F is the body tile. Name it for what the code shows (a body on the map) and drop "cloud edge".
- [ ] must-fix ConsumeScrollSpell: the header and the constant `NameNumberRedrawBelow` say the scroll is "handed to RemoveInventoryItem to redraw". RemoveInventoryItem (res12 00BA:1509, registry note) unlinks the item from Who^.Items and frees it; nothing is redrawn. So the scroll is deleted when NameNum[2] drops below $D2 (a used-up scroll). A consumed scroll is the game behaviour here and the comment misstates it; rename the constant and say what NameNum[2] counts if known, else mark it `Purpose unknown`.
- [ ] must-fix InitSpellHandlers: the header calls `ItemAffectUse` "the combat-only-spell flag". POOLVARS says it is True while the Use action casts a spell through CastChosenSpell (an item cast; SpellCasterLevel returns 6, SpellAreaSize multiplies by 6), and CastChosenSpell uses it exactly so (no ForgetSpell, "That Item" text). It is not a combat-only flag.
- [ ] must-fix AddItemSpells: `HasAffect(SelectedCharacter, $10, ...)`, the item class `$0C` and the pending tests `> $80` are bare meaningful numbers, and the header does not say what they are. $10 is the Read Magic affect (row 18 Read Magic has AffectId $10; ovl12's `IgnoreAffect` runs for affect $10): a character under Read Magic sees the hidden names of the item's spells, and a cleric sees scrolls of item class $0C. Name `ReadMagicAffect`, name the item class and the pending bit ($80, as `SpellMask` in ConsumeScrollSpell), and say in the header why HiddenNames is cleared. Same bare $7F and $80 in AddSpellMenuLine and BuildSpellList (`Spell and $7F`, `> $7F`) where ConsumeScrollSpell already has `SpellMask`.
