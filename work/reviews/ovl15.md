## Findings

- [ ] should-fix `ovl19_e12`'s second argument: the calls pass `(ListMemorized, 1, ...)`, `(ListLearnable, 2, ...)`, `(ListScrolls, 3, ...)` and `(ListMemorizing, 0, ...)` / `(ListScribing, 0, ...)`: the second argument is the action number (1 cast, 2 memorize, 3 scribe, 0 none) that the unit already names `ActionCast`, `ActionMemorize` and `ActionScribe` for MayUseMagic. Use the constants at these calls (and a `NoAction = 0`), and say in the `ListXxx` comment which argument is which. The `ListXxx` values are documented as "as the camp uses them" (an inference from the call sites: ovl19 is not decompiled); keep that wording, tag it [I].
- [ ] should-fix `ovl22_e6` is read as "the item is a scroll": the comments say "an item ovl22_e6 accepts, a scroll" and "every scroll Who carries (an item ovl22_e6 accepts)", and the whitepaper 5.22 says "a scroll (`TMenuLine.Affects[1..3]` of an item `ovl22_e6` accepts)" as [V]. ovl22 is not decompiled; the only support is `ScribeScrolls`' message 'has no copyable scrolls' and ovl09's use of the same function negated in `UseMagicItem` (whitepaper 5.5.3). Mark the reading [I] in the three routines (StudyRestMinutes, CancelScribing, ScribeScrolls) and in 5.22 until ovl22 settles it; the unit comment's "become real only through the rest (ovl20_e2)" is [I] in the whitepaper and stated as fact in the unit comment, hedge it there too (ovl20 is in progress by another decompiler).
- [ ] should-fix magic numbers that are named elsewhere in the same unit: `SelectedCharacter^.Status = 1` in MayUseMagic (dead: ovl04's `StatusDead`), the window and rows (`DrawWindowFrame(1, $11, $26, $16, 0)`, `ClearWindow(1, $11, $26, $16)`, `ClearWindow($11, 1, $26, $0B)`, `DrawTextAt(1, $12, ...)`, `Row + $11`, `Col := $13`) next to the named `ListLeft..ListBottom`, and the bare `60` in StudyRestMinutes (`MinutesPerHour`). The colours, keys, spell-bit masks, hours and levels are all named, which is good.
- [ ] should-fix AlterMenu: the local `Choice: Char` holds a key, not a choice; rename `PicsKey` (or `Key2`). The Pics loop casts the bytes `ShowMonsterPics` and `ShowPortraits` to Boolean (`Boolean(X) := not Boolean(X)`), which says the variables are flags: declare them `Boolean` in POOLVARS (the comment there already says "nonzero: ..."), if the other users compile the same, and drop the casts. The comment says "I ovl16_e3 and a redraw" without saying what the Icon command does; say "Purpose unknown: ovl16_e3 (menu text 'Icon')" or what it changes.
- [ ] should-fix ScribeScrolls: the final loop (`Item^.Affects[I] = Spell` on every item) does not test `ovl22_e6(Item)`, while the loop before it, the cancel and the rest-minute loops do; an item that is not a scroll but has an affect byte equal to the spell number would get its byte marked. Mark it `QUIRK ovl15:xxxx` (address in the packet), since the comment lists the checks of this routine as if complete. Also `Unused: Byte` here and `Unused: Word` in RestParty are frame-only locals without a comment.
- [ ] should-fix `ds6DB5` (CastSpells, MakeCamp: "set to nil when the camp opens and closes and before casting") and `ds6DD8` ("cleared when the camp opens; meaning unknown"): both are documented in POOLVARS, but the routine comments only say "Clears ds6DB5 first". Add `Purpose unknown:` with what is known (a pointer cleared before spell use; ovl22_e5 and ovl19 may read it), as ds6DD8's POOLVARS comment already does.
- [ ] should-fix cross-unit naming of the affects (note for Phase 6, not a defect of this unit): this unit names `$1F` Helpless, `$32` Dreaded Mummy Disease, `$2C` Cause Disease and `$37` Poisoned from the strings the Display command prints, which are the best evidence in the source; ovl24 calls `$1F` `AffectNausea` and `$32` `AffectHealingBlock` (inferred from effects), and ovl04's `AffectPoison2`/`3` ($16, $0F) and `AffectDeath` ($20) have no support: Display shows `$0F` as unnamed (it is not in either case list) and `$16` as a spell affect named by SpellNames. Since `$37` = Poisoned, ovl04's `AffectPoison` is now confirmed by a string. Record the names in one table.
- [ ] note PartyOrderMenu, CampMagicMenu, AlterMenu, CampSpeedMenu and MakeCamp pass `ExtKeys = 1` to ReadPromptChoice and send the extended key to `ovl19_e10` (G = Home, O = End: whitepaper 5.22 "Extended keys (G and O) go to ovl19_e10 in every camp menu") or use the arrow scan letters directly (CampSpeedMenu: P = Down arrow lowers `GameSpeed`, H = Up arrow raises it). This is the same convention ovl25 documents (ExtKey = 1 when an extended key or a digit key was returned); the comments say "an extended key goes to ovl19_e10", correct. The QUIRK at ovl15:1BC6 (F and S do not test the bounds, the prompt offers them only inside 0..9) holds: the arrow keys do test them.
- [ ] note MemorizeSpells: the search `while SelectedCharacter^.Spells[Slot] <> 0 do Inc(Slot)` has no bound; a full Spells array (21 slots) would run on, as in the original. Not marked as a QUIRK; one clause would do. The two prompts differ by one letter ('Memorize These Spells? ' before, 'Memorize these spells? ' after), the same in ScribeScrolls, correct.

No inline code, no assembler routines; the unit comment states its purpose and cites whitepaper 5.22; every `dsXXXX` global it uses has a POOLVARS comment; the stub signatures it sets (`ovl19_e12`, `ovl20_e2`) are recorded in the registry.
