## Findings

- [x] must-fix ShowPagedText `MoreKeyLine`: the constant is commented "ShowMessageLine row for the paging prompt", but `ShowMessageLine(Color, Text)` takes a colour as its first parameter and always draws on row 24 (ShowMessageLine itself, 0709:0BF5, and whitepaper 5.15: "ShowMessageLine(13, ...)"). $0D is colour 13, not a row. A porter who believes the comment would draw the prompt on row 13. Rename to `MoreKeyColor` and say "colour of the 'Press any key to continue' prompt". (fixed in 99cec50)
- [x] must-fix SetActivePage (0709:0071): the comment reads "Sets the EGA/VGA plane the video BIOS page A points at: writes AH=5 ... and AL=A into Regs". `A` is a leftover parameter name (the parameter is `Plane`), and the thing is a display page, not a plane: INT 10h AH=5 is "select active display page" and the value goes in AL; POOLVARS already calls `ds4A1A`, the value passed to SetPlaneSegment, "display page" and whitepaper 2.3 says POOL.CFG 'E' selects VideoAdapter 1 and EGA mode $0D. The segment `Plane shl 9 + $A000` is a page start ($200 paragraphs = 8000 bytes per page). Rewrite the comment and rename the parameter `Page`. The same word is wrong in `SetPlaneSegment` ("EGA/VGA plane segment"), `FillPlaneRect` (parameter `Plane`, "on one EGA plane") and the POOLVARS comments of ds4A16 and ds4A18; fix those together (see the next finding for the routine names). (fixed in 99cec50)
- [x] should-fix SetPlaneSegment, FillPlaneRect, ClearFullScreen, ClearRect: besides the parameter name, `SetPlaneSegment` should be `SetPageSegment` and the `Plane` arguments `0, 1` in ClearFullScreen and ClearRect are the two display pages (the pair `ds4A16`/`ds4A18` that DrawGlyph mode 1 writes to), while "planes" in DrawGlyph mode 0 and 2 and in ClearFullScreen mode 0 and 2 are CGA/Tandy scanline banks ($B800/$BA00 ..$BE00). Use "page" for the first meaning and "bank" for the second; `make rename OLD=SetPlaneSegment NEW=SetPageSegment WHY="its argument is the display page ds4A1A and the INT 10h AH=5 page number, segment $A000 + page * $200"`. (fixed in 99cec50)
- [x] should-fix ShowPagedText QUIRK 0709:0919: "the outer test already took M > Right": `M` does not exist in the source (the test is `(J - I) + GlyphCol > Right`). Say that, e.g. "the enclosing test already took (J - I) + GlyphCol > Right". (fixed in 99cec50)
- [x] should-fix ShowPagedText: `Bottom` is tested against `MaxCol` ($27), not `MaxRow` ($18), at the first line of the body (the constant's comment says "loosely", whitepaper 5.15 says "Bottom is tested against 39 too"), but the routine comment has no `QUIRK 0709:xxxx` for it, which the convention asks for ("every behaviour a port must keep although it looks wrong"). Give the address (the `cmp` of Bottom against $27 in the packet, early in 0709:0768) and mark it, as DrawTextAt marks its row test. Also `I` and `J` are the start and end of the word being measured, not loop counters: name them (`WordStart`, `WordEnd`); READABILITY allows `I`, `J` only for loop counters (the comment on `J`, "Text char past the word end", also disagrees with DrawTextRun drawing `Text[I..J]` inclusive: say "last character drawn: the blank or break character that ended the word, or the last character of the text"). (fixed in 99cec50)
- [x] should-fix ReadInputLine `Col`: commented "screen column of the last character shown", but it starts at `Length(Prompt)`, the cell after the prompt's last character, and is incremented before the first typed character is drawn, so the echo starts one cell after the prompt's end and a blank cell separates them (and Backspace clears `Col` then steps back). Either the prompts end with a space and this is a deliberate gap, or it is an off-by-one worth a `QUIRK`; say which, and fix the comment. The magic numbers `$27`, `$18` and `24`/`40` are named in some routines (DrawGlyph, ReadInputLine, FlashMessageLine, ClearFullScreen) and bare in others (ClearTextCells, DrawTextAt, ShowMessageLine); use the same constants everywhere (`LastCol`, `LastRow`, `BottomRow`, `ScreenCols`). (fixed in 99cec50)
- [x] should-fix GameClock (0709:0C3F): the comment says the Word multiplies drop the high word (QUIRK 0C75, 0C85) but not what that does. `Minute * 6000` overflows 16 bits for any minute from 11 up (11 * 6000 = 66000), so the returned value falls back by 65536 for each overflowed minute term within an hour; `Second * 100` (at most 5900) can never overflow, so 0C85 is harmless. Whitepaper 5.15 already says "a minute above 10 loses its carry"; put the consequence in the routine comment and mark which of the two multiplies matters (WaitKeyOrTimeout and ShowTitleScreen compare it with a deadline, `GameClock >= Limit`, OVL01.PAS lines 31 and 136, so a deadline set just before a wrap can be missed or met at once). (fixed in 99cec50)
- [x] should-fix ShowMessageLine (0709:0BF5): the comment is a single line ("show a one-line message on row 24 and wait for a key"). It should say what Color and Text are, that it first clears row 24 (40 cells), that the key is read through ReadGameKey and discarded (the local `Key` is assigned and never read, which belongs in a QUIRK or a local comment), that no result is returned, and name `BottomRow`/`ScreenCols` as FlashMessageLine does. It is called from twelve places. (fixed in 99cec50)
- [x] should-fix port numbers: `$3CE/$3CF` (EGA Graphics Controller index/data), `$3C4/$3C5` (Sequencer index/data) and their register numbers and values (`Port[$3CE] := 5; Port[$3CF] := 2` is "Mode register, write mode 2") are bare in SetEgaFillRegisters, FillPlaneRect and DrawGlyph. The comments explain SetEgaFillRegisters well, but FillPlaneRect only says "GC index 5 to 2" and `$0F`/`$FF` are bare. Name the ports and registers (`GcIndex`, `GcData`, `SeqIndex`, `SeqData`, `GcMode`, `WriteMode2`, ...), in the same way `MapMaskRestore` is named in DrawGlyph and still used beside a bare `Port[$3C4] := 2`. (fixed in 99cec50)
- [x] should-fix DrawGlyph (0709:01DF): (a) the comment ends with "revisited when DrawGlyph itself is reviewed": decide it here: `Glyph: Byte` and `Cook: Byte` stay, because ovl02's callers pass Integer expressions and the constant 1 for Cook (a Boolean parameter would not accept it), so say that and remove the promise; (b) `Cook` is a vague name, say `Uppercase` or `TextSet` (it upcases and wraps into the 64-glyph text set); (c) the local comment "A*4 byte column base" names a variable that does not exist (`ColBase := Col * 4`); (d) in mode 2 `DestOff` holds the font row and `FontRow` the destination graph row, the reverse of the names (documented in the local comments, accepted because the slot order is fixed by the original frame, but mark it `QUIRK` or `Purpose:` so a porter does not copy the names); (e) with `Cook = 0` the raw `Glyph` can exceed 176, the last of the 177 glyphs of TFont, and reads past the font block (range checks are off); a note is enough; (f) the `case` is indented two columns less than its `for`, which hides the loop structure when read. (fixed in 99cec50)
- [x] should-fix LoadGameFont: `FontBlockId = $C9 { ... (whitepaper 4.x) }`: cite the section. The block is described in whitepaper 4.2.3 ( "`8X8D1.DAX` block 201 ... a 1-bit font, 177 glyphs of 8 bytes each") and 5.15. (fixed in 99cec50)
- [x] should-fix DelayCounted (0709:0DBE): what is "counted"? The routine is `Delay(GameSpeed * 225)`. The name says nothing the code shows; prefer `DelayByGameSpeed` (rename) and keep "225 milliseconds per GameSpeed step" in the comment. (fixed in 99cec50)
- [x] note: the 'retf n: n bytes of parameters; n bytes of locals' comment lines above SetEgaFillRegisters, SetActivePage, SetPlaneSegment, FillPlaneRect and DelayCounted duplicate the next comment's address and are noise; keep one comment per routine. (fixed in 99cec50)

### Round 2 findings

- [x] must-fix unit `var` block comment (RES06.PAS lines 61 to 64): "the EGA display pages ds4A16/ds4A18 (SetActivePage) are this memory seen with a page selected" is false. The pages are at segment `$A000 + Page * $200` (`add ax, 0xa000` at 0709:0096 and 0709:00AD, as the SetActivePage and SetPageSegment comments say), a different memory from the CGA/Tandy banks `$B800..$BE00` that TextPlane0/1 and GraphPlane0..3 overlay. A porter who believed it would alias the EGA pages with the scanline banks. Say that the planes are CGA/Tandy video memory (VideoAdapter 0 and 2) and that the EGA pages (VideoAdapter 1) live at `$A000` and `$A200`, reached only through ds4A16/ds4A18. (fixed in 2d31648)
- [ ] should-fix TextPlane/WordPlane comments and ClearRect constant `ScanlinesPerTextRow` (RES06.PAS lines 36, 567; DrawGlyph comment line 160): "4 scanlines per text row" is per bank. A text row is 8 pixel scanlines, 4 in each of the two banks (even scanlines in `$B800`, odd in `$BA00`; DrawGlyph mode 0 writes `Row * 4 .. Row * 4 + 3` in both). Say "4 rows in each bank (8 scanlines)" so the constant is not read as the total. `TWordPlane` is said to have "200 rows of 40 words" but a bank holds 100 rows of 80 bytes (8000 bytes, as TTextPlane); the extra rows are only there to keep the type wide, say that or why.
- [ ] should-fix FillPlaneRect (RES06.PAS lines 123, 132): `40 * 8` and `Inc(DestOff, $28)` are bare while the unit has `ScreenCols` (40) and DrawGlyph has `GraphStride = $28` (the same 40 bytes per scanline); round 1 asked for the same constants everywhere. Hoist `GraphStride` to the unit constants and use `ScreenCols` and the 8 scanlines per cell row as a named constant. The `RightCol - LeftCol + 1` is the byte count (a cell column is one byte on the EGA page), say so in the comment.
- [ ] should-fix whitepaper 5.15 (checklist item 10): the DrawGlyph entry still reads `DrawGlyph(Col, Row, Color, Count, Glyph, Cook)`, but the parameter is now `TextSet`; "the two EGA pages per plane" should read "the two EGA display pages (ds4A16/ds4A18), one write per plane through the Map Mask". The `re/symbols.toml` notes still say "EGA plane" for FillPlaneRect, SetActivePage and ClearFullScreen (history of the renames, accepted as such; the source is the current word).
- [ ] note DelayByGameSpeed: the comment has a stray line break ("No parameters. Called while / drawing many screens"); harmless. "225 milliseconds per step" is the code's constant (`Delay(GameSpeed * 225)`), not a measured duration; fine.
- [ ] note ReadInputLine: the QUIRK 0709:0A7E reads well; only OVL02's CheckCodeWheel calls it (prompt `'INPUT THE CODE WORD: '`, ends with a blank), so the first echo sits two blank cells after the last prompt letter. The comment says the gap is the original's; that is true and enough.
