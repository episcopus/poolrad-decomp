- [x] must-fix RunCharacterMenu / TrainCharacter: the constant `Var2OfferModify = 680` ("the modify function is offered while it is above 0; unknown") is a false name. The code sets `ds0619[3].Present`, which is slot 3 'Train Character' (DS:0619, see above), and TrainCharacter (ovl16:29AE) uses the same word as a class-bit mask: the Train command needs `ds49D6^[680]` to share a bit (ds05DE class bits) with the character's classes and with a trainable class, else 'We don't train that class here'. So word 680 is the set of classes this hall trains (a mask of ds05DE bits, low byte only), and Train is offered while it is above 0 (or ds470C is set). Rename it for that (`TrainableClassesWord` or similar) and fix its comment; the POOLVARS comment of `ds470C` ("the menu offers Modify") is wrong for the same reason (it offers Train) and needs fixing by whoever owns that record. Also tag the 680 reading [I] unless the writer is found (the whitepaper 5.8 text already calls it "the hall's word"). (fixed in 3dc70f8)
- [x] must-fix FreeCharacter: the comment says it "clears the caller's pointer (Char := nil)". `Who` is a by-value parameter, so `Who := nil` is a dead store and no caller's pointer changes (RemoveSelectedCharacter reassigns SelectedCharacter itself right after). There is also no `Char` in the routine. Correct the comment and mark the dead store `QUIRK ovl16:00xx` (address from the packet; the registered signature is `FreeCharacter(Who: PCharacter)` by value, see probe tools/re/tp_idioms/ovl16/FREEPRM.PAS). (fixed in 3dc70f8)
- [x] must-fix CreateCharacter: the age paragraph is wrong for two cases. It says a multi-class age is the maximum of the entry "from the first of the combined classes in the entry order cleric, fighter, magic-user". The code (and whitepaper 5.8) use the Cleric entry for masks 8, 9, $B, $C, the Fighter entry for $E, but the Magic-User entry for $D (Fighter/Magic-User), $F and $10, which a "first in order" rule would not give for $D and $F. Add this to the routine comment (with tag [I] if kept to what the two units show) and a comment at the statement; ideally the field is named in TCharacter (a shared record, so by the decompiler of ovl12 or through the orchestrator).
