## Findings

- [ ] should-fix ReadPromptChoice, keypad digits: the comment and the whitepaper say "the keypad digits return the scan letter of their key (KeypadScanLetters)". The code converts the digit characters '1'..'9' (and '\') that `ReadGameKey` returns, so the number row and the NumLock keypad both do it; the game cannot tell them apart. And the conversion (`if ExtKeys <> 0 then if Key in ['1'..'9', KeypadBackslash]`, after the hotkey search) overrides a digit hotkey that was just matched: with ExtKeys nonzero a prompt word starting with a digit can never be picked by its digit. Say "the digit keys 1 to 9", and mark the shadowing as a QUIRK (it affects the Rest menu `Rest daYs Hours Mins ...` style prompts and ChooseFromList, which passes ExtKeys = 1).
- [ ] should-fix ReadPromptChoice, hotkey search: the loop `for I := 1 to PromptLen do if Prompt[I] = Key` does not stop at the first match: it sets `Done` and `PromptWordChoice` on every matching character, so when two words begin with the same capital the last one wins (and a match that is not a word start runs `while Words[J].Start <> I` off the end, which QUIRK 0662 covers). Mention "the last matching word wins" next to QUIRK 0662; whitepaper 5.8 says "a capital or digit that begins a word chooses it" and omits both.
- [ ] should-fix ChooseFromList: `KeyPrevPage`/`KeyNextPage` ('P', 'N') call `ScrollListPage` with no `HasPrev`/`HasNext` test, while PgUp/PgDn are guarded. So any prompt that contains a word beginning with P or N turns the page whether or not " Prev"/" Next" was added; with fewer lines than the window, `ScrollListPage(True)` sets `ListMenuTop := LineCount - Height`, which is negative. Mark as `QUIRK ovl25:xxxx` with the address of the two arms (`ovl25:1042..1066` per the constants' comment). Likewise `KeyEscape` in the same arm is dead (ReadPromptChoice turns Escape into #0 before returning): say so.
- [ ] should-fix ChooseFromList entry: `Inc(Choice); MoveListCursor(False)` leaves Choice where it is, except that a heading is skipped upward and a Choice past the last line is clamped: the Inc cancels the Dec inside MoveListCursor. That is a real idiom (normalise the caller's Choice) and deserves one sentence in the routine comment and a QUIRK or comment inline; the routine comment only says "highlights line Choice (0-based)". Also the comment says " Prev" appears "when there are more lines ... above the page", but `HasPrev` is `ListMenuTop > HeadingCount` (the number of leading heading lines), so a page that starts inside the leading headings has no Prev.
- [ ] should-fix ChooseFromList comment, "Home and End move the highlight": say what they do (one line up for Home, one line down for End, wrapping inside the page and skipping headings, `MoveListCursor`); the unit comment says "(Home/End, with Next/Prev/Exit words added to the prompt)". Whitepaper 5.8 has the direction right; copy it.
- [ ] should-fix AskYesNo: `PromptWordChoice := 2` is a bare 2 (the "No" word, which the comment mentions) and the comment does not say that the highlight is cosmetic: Enter and Space return #13 and ' ', which are not in `[KeyYes, KeyNo]`, so the loop asks again; only Y and N end it. A port that makes Enter pick the highlighted word would change the game. Add that sentence and name the 2 (`WordNo`).
- [ ] should-fix ClearPromptLine: "Called by the loader (ovl07, ovl11), the area keys and many other units": the packet's callers are ovl07, ovl08, ovl09, ovl10, ovl11, ovl13, ovl15, ovl16 (3) and ovl17 (2). ovl07 is the script operand and menu unit (whitepaper 5.x), not a loader, and no ovl14 area-key code calls it. List the callers as the packet shows them. The same for ReadPromptChoice ("ovl14's area keys" is right per OVL14.PAS; add ovl15, ovl20, ovl21 which also call it).
- [ ] should-fix parameter names: `ExtKeys` (the caller accepts extended keys) and `ExtKey` (the result flag) differ by one letter in the same signature, and `Animate` is passed to DrawSprite as `Direct`. Prefer `AcceptExtKeys` and `WasExtKey` (and say what `Animate` means in the signature comment); many other units pass them positionally, so the rename is local.
- [ ] should-fix magic numbers: `ReadPromptChoice(..., 1, 0, ExtKey)` in ChooseFromList (ExtKeys = 1, Animate = 0), `MoveListCursor(False)`/`(True)` as the Home/End directions (fine, commented), and `'\'` to `'7'` (`KeypadBackslashKey`) whose purpose nobody gives: either add `Purpose unknown:` with what is known (the whitepaper says only that `'\'` gives `'7'`; '7' is not a scan letter of ChooseFromList's table either, so the key is ignored there) or find the caller that uses it.
- [ ] should-fix `LastNonBlank`: the comment says "1 when all are blanks" but an empty text (Length 0) returns 0 (`I := Length(Text); while (I > 1) ...`), and `HighlightListLine` then computes `Len := 0 - First + 1 = 0` and copies nothing. Add "0 for an empty text".
- [ ] note ReadPromptChoice: "Enter returns #13 when either colour is nonzero" means WordColor or HotColor (`AcceptsEnter`), not TitleColor; whitepaper 5.8 has the same wording. SplitPromptWords has no bound at `MaxPromptWords` (20 spans, 40 bytes), documented only in the constant's comment; a prompt of more than 20 words would overflow `Words`.
- [ ] note FreeMenuList QUIRK ovl25:11F3 is correct (`List` still points at the freed first line; HealMenu in ovl04 resets nothing and does not reuse it). NewMenuList allocates at least one line even for Count 0, correctly stated.
- [ ] note whitepaper 5.8 (lines 731..735) matches the unit, including the arrow-key oracle observation and the `ovl25:0FF4..102A` scan-letter evidence; it should pick up the two keyboard findings above (digit keys, P and N unguarded) when they are confirmed.
